# 2 分钟演示脚本（面试/录屏用）

目标：用最短时间让面试官相信「这个人真的写过 LLM 应用，且覆盖了我们 JD 的要点」。
节奏建议：架构图(20s) → 真实中文 RAG(40s) → 流式+降级(40s) → 评测与成本(20s)。

---

## 0:00–0:20 开场 + 架构（边指 README 架构图边说）

> 「这是我做的一个多模型 Agent 对话工作台，核心是用一套统一接口把多家 LLM、RAG、消息队列和评测串起来。
> 蓝色是请求主链路，右侧评估与观测是单独旁路。下面我直接跑给你看。」

不用现场讲代码，指图即可，把话术落到 JD 关键词：**asyncio 流式、LangGraph、RAG、多模型降级、消息队列、评测**。

---

## 0:20–1:00 真实中文 RAG（最能讲的点）

先把知识库起来（终端已 `docker compose up`）：

```bash
python scripts/reset_db.py
python scripts/seed_demo.py
```

打开页面 `http://localhost:8000`，在右侧检索框输入「质量问题退货的运费谁承担」，回车：

> 「这是 RAG 的检索环节。知识库是一份电商退款政策，我故意用中文 BGE/OpenAI embedding 而不是默认英文模型——
> 这里有个坑：朴素切块会把条款拦腰截断，所以我按段落+句子切、带重叠；检索回来还带了出处，方便模型引用。」

---

## 1:00–1:40 流式输出 + 跨供应商降级

左侧聊天框输入：「根据知识库，告诉我退款多久到账、质量问题运费谁出？」

> 「这是 FastAPI 的 SSE 流式返回，asyncio 驱动，边生成边吐字。
> 气泡下面那行『本回答由供应商：xxx』是降级痕迹——如果主供应商 5xx 或限流，会自动切到下一个，对前端透明。」

（演示 failover：可临时把 `.env` 里主 Key 改错一个，发消息看自动切换 + 气泡标注变化。）

---

## 1:40–2:00 评测 + 成本可观测（加分项收尾）

```bash
python scripts/run_eval.py
curl http://localhost:8000/metrics
```

> 「最后这块是加分项：我用 LLM-as-judge 给 7 条业务问答打分做回归，
> 成本不是估算的，是从模型 usage 真实统计的 token 数——跑一轮花多少、哪个环节最贵一目了然。」

---

## 备选追问的应答要点（背一下，别现场编）

- **朴素 RAG 为什么翻车**：切块粒度、中文 embedding 选错模型、检索无出处 → 本项目逐条有对策。
- **流式一致性**：SSE 断流/重连如何幂等、不重复生成（可说用 session 去重 + 客户端去重）。
- **为什么多模型接入层**：屏蔽厂商差异、做降级/限流/成本统一管控。
- **长期记忆**：当前消息落 PostgreSQL，可演进为「会话摘要压缩 + 用户画像」。
